# P06 — Quantum Circuit Synthesis for AES with Low DW-cost

## 论文做了什么

本文利用复合域求逆中的中间值清除输入，构造直接原位 S-box，再配合有限域乘法和密钥扩展优化，降低 AES 的非线性深度×宽度成本。当前使用 S01：2025-11-27 修订版；身份与引用键见[共享注册表](../../landscape/papers.json)，研究定位见[地图](../../landscape/report.md)。

## 读者问题

### Q01 — 这篇论文最大的贡献或创新是什么？

2026-11-11：已回答。助手判断，核心方法创新是复合域求逆的直接原位构造：利用 θ 和求逆结果重建并异或清除原输入，再利用输出清理剩余中间量，避免把完整正向/逆向 out-of-place S-box 当作黑盒拼接。依据 §1.2、§3.1 Theorems 1–2 与 §3.2。此处“最大”是对作者技术链的归纳，不是论文证明的创新排名。有限域乘法并行化及轮函数/密钥扩展协同设计是实现低 DW-cost 的配套贡献。

Table 3 报告原位 S-box 宽度 23、计数口径下 Toffoli 深度 12、乘积 276；Table 4 报告 AES-128 宽度 544、深度 120、乘积 65,280。§2.3 的深度不计可替换为 QAND† 的清理门，因此不能称为总逻辑深度或严格酉 NCT 深度；也不能把 Table 4 的改进比例称为完整 Grover 攻击成本降幅。未独立复现电路或逐一核验所有历史基线。

### Q02 — 电路一直向前执行，为什么多轮过程中还要逆运算和重置？

2026-11-11：已回答。区分 AES 内部轮次和 Grover 迭代：局部反计算保留本轮输出，清除旧输入/临时量以复用空间，并非每轮把整个叠加态恢复到最初；允许保留垃圾并延后清理，但需承担宽度和后续清理成本。相位 oracle 的反计算则清除与候选密钥相关的工作寄存器，保留标记相位，以满足标准密钥寄存器扩散的接口。逆电路仍按时间向前执行，只是门序倒置且各门取逆，不需经典获知每个叠加分支的输入。S-box 可逆，能利用输出及中间量清理旧输入。依据 S01 §2.3、§3 Fig. 2 与 §3.1；Grover 解释参照 S02，公式为助手重构。直接测量/丢弃与密钥纠缠的垃圾一般不能替代相干清理；测量辅助反计算需专门的反馈校正结构。

### Q03 — 宽度无限是否就不需要中间逆电路或可逆性？

2026-11-11：读者提出：中间逆电路主要源于有限宽度和比特复用，宽度无限时可不清理。助手判断：对 AES 内部的局部反计算，这一理解在允许保留垃圾的条件下成立，可以用更多空间推迟清理；但“不必立即运行逆电路”不等于“不需要可逆性”，酉计算仍必须整体可逆，保留历史信息恰能保证这一点。对本项目标准相位 oracle，标记后与密钥相关的垃圾仍需消除或解纠缠，以供密钥寄存器上的标准扩散使用；无限空间本身不能解除纠缠。依据 S01 §2.3、§3 和 S02 所追溯的 Grover 接口，属于助手对适用边界的解释，未新增论文最优性判断。

### Q04 — “消除工作寄存器与候选密钥之间的纠缠”是什么意思？

2026-11-11：已解释。助手构造双分支示例：计算后密钥 0/1 分别关联工作状态 g(0)/g(1)，若这两个计算基状态不同，则整体不能分解为两个独立纯态。只在密钥上操作时，不同工作标签对应的振幅不能作为同一完整基态的振幅相加。以 Bell 态和无纠缠的加态对照，密钥上施加 H 后，前者两种测量结果各占一半，后者确定得到 0；此例仅说明干涉，不是完整 Grover 搜索实例。反计算把两分支工作状态统一为零，同时保留标记相位，使整体重新分解为密钥态与全零工作态。纠缠本身不是错误，限制来自后续仅作用于密钥的标准扩散接口；也不声称只要存在任意垃圾就完全没有干涉，工作状态相同的分支仍可干涉。来源沿用 S02；示例和公式为助手教学重构。

### Q05 — S-box 利用中间值反计算，发生在 Grover 的哪个阶段，如何节约成本？

2026-11-11：已解释。该方法主要位于 AES 正向求值内部的 SubBytes S-box，是局部清理：保留 S(x)，利用复合域中间量和输出清掉旧输入与辅助量。它不是等到 Grover 相位标记后才运行的整段 AES 反计算，也不取代后者。标准 oracle 层次为 AES 求值（内含局部清理）→比较与相位标记→撤销比较和 AES 求值→扩散。优化后的小组件也影响外层反计算成本，但测量辅助实现不能机械地把所有门逐个取逆，计费需采用相应构造。来源 S01 §3 Fig. 2、§3.1、§3.2 Fig. 3（p. 13）、§5 开头；本次补查 §3.2 全部文字。优势来自不再以两套完整 out-of-place S-box 黑盒组合实现原位变换，并通过小域组件协同调度降低局部 DW-cost；集成收益见 Tables 3–4，不等于所有资源指标同时降低。原位结构并非零辅助比特：Table 3 宽度 23 包含临时工作位。

### Q06 — 增加宽度、保留 S-box 中间状态，能否换取最短深度？

2026-11-11：已回答。读者提出用空间替代 S-box/轮内清理来降低一次候选密钥求值的深度。助手判断：这是成立的空间—时间折中方向；允许保留垃圾的计算接口与干净原位 S-box 不同，删除不再必要且不影响后续依赖的清理可降低或不增加该给定前向构造的深度，新增空间也可支持原本因空间不足而串行的操作并行。但不保证严格下降，更不证明全局最小深度：数据依赖仍存在，有些清理已与其他操作重叠，QAND† 清理可不贡献 T-depth 却仍有测量/反馈成本。标准完整 oracle 仍需相位标记后的工作空间清理；以酉构造示意，成本为前向计算、比较标记、整体逆计算之和，具体测量辅助实现另行核算。§3 Fig. 2 后段已讨论推迟清理、并行执行及宽度代价；§3.2 明确区分低 DW、低宽度、低深度策略，Table 4 显示本文 120×544 与比较项 40×3048 的折中。未将读者构想记为新颖算法或已证最短深度。

### Q08 — 第一项中间值清理创新与第二项低 DW-cost S-box 是否是同一条贡献链？

2026-11-11：读者认为第一项结构创新导致第二项低 DW-cost 结果。助手判断：这一因果方向成立，但第二项不只是第一项的数值复述。§3 提供利用中间值清除输入的直接原位求逆结构，§4 另有有限域乘法的 Toffoli 并行化条件（Theorem 3）及多个非线性组件的协同选择，才形成 Table 3 的宽度 23、深度 12、DW-cost 276。两项是有依赖关系的结构层与组件实现层贡献；不能把最终降幅全部归因于第一项，文中所检查内容没有将各项贡献的收益独立量化。依据 S01 §1.2、§3.2、§4 Theorem 3 与 Table 3；本次补查 Theorem 3 的陈述、证明与后续解释（pp. 15–16），未作最优性证明审计。
