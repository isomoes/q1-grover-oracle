# AES/Grover 电路选题：已有指标改进，还是新的评价角度？

**结论：建议以“已有指标上的可复现方法改进”为主线，以“真实资源约束下的评价与解释”为副线。** 最值得先验证的方向是：宽度受限、测量反馈延迟可变时，完整 AES-128 Grover oracle 的跨轮、密钥扩展和多明密文对清理调度。这个方向目前是**研究假设**，新颖性和收益均待验证。

检索日与本次截止日：**2026-11-11**；近期窗口：2024-11-11–2026-11-11，历史先例单独追溯。本报告是对[原有五路线地图](../landscape/report.md)的定向扩充。新增 P21–P28 为竞争者和方法先例，不代表完成了全领域更新。引用身份与版本见[注册表](../landscape/papers.json)，引用键见[参考文献](../landscape/references.bib)。

## 1. 两条论文路线的成熟度与门槛

| 维度 | 路线 A：在已有指标上做得更好 | 路线 B：提出有依据的评价角度并优化 |
|---|---|---|
| 已有进展 | 从门数、宽度、T-depth，发展到 DW、全深度、轮／密钥联合调度与完整搜索成本 | 已有主动／被动量子存储模型、限时并行搜索、辅助比特存活体积、架构相关 active volume 和 reaction depth |
| 竞争情况 | AES S-box 和线性层竞争强，2025–2026 仍有具体方法与实现改进 | 工作分布于密码、量子编译和容错架构；看似空白的角度经常已有跨领域先例 |
| 核心证明责任 | 方法差异 + 正确性 + 同口径强基线 + 改进／退步的完整资源表 | 为什么旧评价会误导 + 约束的实际来源 + 排名或决策变化 + 对应优化方法 + 参数稳健性 |
| 可发表贡献形态 | 新构造、调度算法、特定结构的优化理论，或有清楚机制的可复现资源改进 | 有外部依据的成本模型及其优化；未必需要发明一个新标量 |
| 主要失败方式 | 只击败旧论文；把加密成本当完整 oracle；不同深度或测量口径混比 | 任意调权重使自己的电路获胜；重命名 DW／存活时间；只增加报表而没有新问题或方法 |
| 当前项目适合度 | **较高**：已有 P03/P06 阅读基础，但尚需建立可运行基线 | **适合作为副线**：物理架构全栈估计更重；先做有明确语义的逻辑约束分析 |

这是基于已核查文献和项目现状的选题判断，不是对论文录用概率的预测。路线 A 也不必要求所有资源同时下降：在相同约束下得到新的非支配点，且能解释适用区间，同样有意义。

## 2. 路线 A：竞争已经推进到了哪里？

### 2.1 历史脉络

- **P02，2015/2016**：明确实现 AES 密钥搜索的可逆电路与 Clifford+T 资源，是早期基线。
- **P03，2019/2020，2023 修订**：把完整谓词、明密文对数、调度和限时并行攻击联系起来；当前最适合先复现，但不是当前最优的代名词。
- **P11–P13，2020–2023**：少比特、低 T-depth、原位轮构造及 S-box/adjoint 共享流水线，说明“用辅助位换深度”和“联合安排反计算”早已是主线。

### 2.2 当前必须考虑的强竞争者

| 工作 | 具体进展 | 对本项目的意义及证据边界 |
|---|---|---|
| **P05，EUROCRYPT 2025** | 最小 T-depth 或最小宽度的不同非线性构造 | S-box 路线的强对手；精确最优性范围仍需核查，不能扩展成全 AES 最优 |
| **P06，ASIACRYPT 2025；11 月 27 日修订** | 利用复合域求逆中间值直接清除输入，结合乘法并行化与密钥调度，优化低 DW | 窄电路候选；Appendix G 的 oracle 估计省略密文比较，采用测量辅助分解 |
| **P14，CIC 2025；ePrint 6 月 22 日修订** | 作者描述 78 种 AES 实现，并分析 MAXDEPTH 与估计器问题 | 低深度／架构路线不能绕开的对手；本轮只复核官方摘要，原始数值尚未统一 |
| **P21，CCQC，Frontiers in Physics 2025-04-22** | 同时针对 TDW 与 FDW，优化 S-box、密钥调度和并行数 | “改看全深度×宽度”已有明确 AES 先例；Table 8 为 forward+adjoint，Table 9 为 forward-only |
| **P22，Chen 等，2025 预印本／QIP 2026-02-11** | 复合域 S-box 与集成密钥扩展，报告 AES-128 的 T-depth×width 为 102,800 | §IV/Table XIV 属于**加密电路**；不能与 P06 的求值／清理部分直接排名 |
| **P15，QCNC 2026；ePrint 2026-03-22** | 从充分清理的功能电路到 Grover oracle 的清理变换 | 与“删除局部反计算、在 oracle 层重排”直接相关，必须先做方法差异核查 |
| **P28，ToSC 2026(2)，2026-06-11** | 利用循环矩阵结构优化线性层；摘要报告自动合成 AES MixColumn 深度 10 | 线性层仍活跃，但达到深度 10 本身已不能算新纪录；门数、结构、调度及全电路效果才可能形成差异 |

P21 原文：[§3–§5、Tables 8–9](https://www.frontiersin.org/journals/physics/articles/10.3389/fphy.2025.1582819/full)。P22 原文：[arXiv v2，§IV-B–D、Tables XIV–XVII](https://arxiv.org/html/2503.06097v2)；期刊身份由 [Crossref](https://api.crossref.org/works/10.1007%2Fs11128-026-05083-7) 核实，未审计期刊版与预印本的全文差异。P28：[arXiv v2 摘要](https://arxiv.org/abs/2511.18226v2)、[ToSC 出版记录](https://tosc.iacr.org/index.php/ToSC/article/view/13012)。

### 2.3 为什么现在不能直接给出一个“全球最佳数字”？

以下都是**原文转录，未运行作者电路**：

| 工作与版本 | 成本对象 | 可核查资源点 | 尚缺的统一条件 |
|---|---|---|---|
| P03 corrected Table 9，AES-128 `r=2`，IP，最小 `G_D²G_W` 分组 | 含比较的 phase oracle | 全深度 3,416；宽度 8,743；T-depth 128 | diffuser 另计；与其他论文统一分解和调度 |
| P06 2025-11-27 Appendix G/Table 10 | 单对求值／清理部分，省略比较 | T-depth 232；宽度 724；乘积 167,968 | 多对数据、比较、标记、diffuser 与全深度 |
| P22 arXiv v2 Table XIV，`c₂²–c₃³` | 含量子密钥扩展的 AES-128 加密 | T-depth 100；宽度 1,028；乘积 102,800 | 完整谓词与清理、多对数据、diffuser |

P22 的“linear key schedule”措辞不能解释为删除了 AES 密钥扩展中的非线性：§IV-B 明确采用 S-box。其 Table XVII 后“same T depth”的表述与表中 100 和 80 不一致，数值比较需要进一步核对。P06 Table 4 的 65,280 则采用排除可由 QAND† 替代层的作者 Toffoli-depth 口径，不能混入上表的 Clifford+T 指标。

**选题含义：统一计费是必要基础，但补比较器、重新算乘积、拼接已知最小组件，并不会自动成为新的优化方法。** 应证明新结构或决策规则在统一计费后仍产生收益。

## 3. 路线 B：哪些“新指标想法”已有先例？

| 想法 | 已有依据 | 还可能研究什么 |
|---|---|---|
| 深度×宽度比单看门数合理 | P03 corrected §3.5 已解释主动纠错存储与被动存储；P06 沿用 DW；P21 同时使用 TDW/FDW | 指定实际约束下哪个指标预测目标成本更可靠 |
| 不同时间占用不同空间，积分比峰值乘深度细致 | **P23 SQUARE，ISCA 2020，§III-B** 已定义 active quantum volume 为各比特使用区间长度之和 | 某架构是否真能释放／复用这些位置；AES 的调度决策与可实现收益 |
| 什么时候清理，应随资源限制改变 | **P23 SQUARE** 已研究局部性、并行性与清理；**P24 Reqomp，Quantum 2024** 已做空间约束自动反计算 | AES 依赖结构或完整相位 oracle 是否提供通用工具未利用的特性 |
| 测量清理虽然省 T 门，却可能受经典反馈限制 | **P25 Active volume，2022 预印本，§1** 明确区分 memory、active volume、reaction depth；P03 §3.3 也计入反馈依赖 | 对具体 AES 电路建立反馈依赖图，找到可靠的策略切换区间 |
| 同时利用并行和测量式清理 | **P26 Parallel Spooky Pebbling，EUROCRYPT 2026**，2026-07-02 修订 | 将合法的 pebbling 模型适配到 AES 的实际依赖图；其现有实验是 Regev factoring，不能直接移植收益 |
| 自动处理 clean/dirty ancilla | **P27 RwUn，2026-08-10 预印本，10 月 11 日 v2** | 借用状态恢复、相位语义与适用域；它不是已验证的 AES 优化结果 |
| 从逻辑指标转向 AES 物理攻击成本 | NIST 第五次 PQC 标准化会议收录 *On the practical cost of Grover for AES key recovery*（2024） | 新硬件假设／映射方法／优化规律，不能声称首次考虑 surface code、蒸馏或物理代价 |

P23 的存活区间之和与 P25 的逻辑操作块 **不是同一种 active volume**。前者可写成 `∑t W_live(t)`；后者依赖特定容错架构与非局域连接。二者都不能直接等同于物理设备购置成本或实际运行时间。

### 一条有说服力的评价路线，需要形成闭环

1. **外部动机**：例如单处理器宽度上限、硬性完成期限、非零反馈时间、有限魔法态供给；约束来源要独立于自己的电路。
2. **旧评价的局限**：用匹配条件的真实候选证明，旧指标可能选错方案；若没有排名变化，也需证明新评价显著改善可行性或成本预测。
3. **清晰语义**：区分存储、活跃操作、空闲纠错和设备容量；权重应来自映射／测量或公开参数范围。
4. **匹配的方法**：由新约束导出调度、重计算、并行或分解选择，而非只重画排行榜。
5. **稳健性**：在合理参数区间、多个宽度预算或不同实例上有效；不以单个人工挑选的点作为核心结论。

因此，路线 B 通常比“定义一个新公式”难。更稳妥的表述是**约束驱动的优化问题与评价方法**，是否需要新指标，取决于旧指标是否确实不足。

## 4. 一个重要的目标变化：DW 与 D²W

令一次**完整 Grover 迭代**的深度为 `d`、宽度为 `w`，搜索空间为 `N`。在唯一目标、固定成功概率 `p`、内部分区并行且单位深度计费一致的近似模型下，令 `cₚ = asin(√p)/2`：

- **单机、无紧迫总深度上限**：总量子比特周期约为 `cₚ√N · dw`。
- **总深度上限为 L，且需要多机满足期限**：约需 `S ≈ cₚ²N d²/L²` 台处理器，总量子比特周期约为 `S w L ≈ cₚ²N d²w/L`。

所以，前一种场景关联 `dw`，后一种关联 `d²w`。后者是 **P03 §3.5 Eq. (10) 的已有结论**，不是本项目提出的新指标。真实计算还需处理整数迭代数、允许的分区数、总宽度可行性、成功率和验证开销；若单机已经能在期限内完成，不能继续套用 `S<1` 的连续近似。

**说明性算例，非论文数据**：若一个方案把宽度降为 0.6 倍，却使深度升为 1.4 倍，则 `dw` 为 0.84 倍，看似节省 16%；`d²w` 却为 1.176 倍，限时模型下反而增加约 17.6%。这说明：论文标题中的低 DW 不自动等于所有攻击场景下都更便宜。实际 AES 是否发生这种排名变化，仍需统一的全深度数据。

## 5. 推荐的主问题及必要差异化

### 暂定问题

> 在宽度预算 B 和测量反馈时延 τ 下，如何调度 AES-128 完整相位 oracle 的计算、保留、反计算与重计算，使完整迭代的深度或攻击相关成本最小？

这里 `d_τ` 应由含量子门、测量、经典条件依赖及资源冲突的实际调度得到；不能直接用 T-depth 代替，也不能未经分析就把测量次数乘时延加到总深度。独立操作可能重叠，可延后的条件修正也需按选定分解明确处理。

建议先以 `min d_τ` subject to `W_peak ≤ B` 建立前沿，再根据目标场景报告 `d_τw` 和 `d_τ²w`。这使用已有资源量，研究贡献应来自**调度方法和可解释的资源折中**。

### 可检验的差异化假设

1. **跨轮／密钥共享决策**：局部最省的 S-box 清理策略未必适合整个依赖图；保留某轮中间值可能同时影响后续轮、密钥扩展和逆向清理。
2. **多明密文对**：`r=2` 时，顺序／并行求值及共享轮密钥存在折中；共享控制位也有门冲突，额外扇出、存储和清理必须计费。
3. **反馈时延下的混合清理**：在合法接口下选择测量辅助或酉清理，可能改变关键路径和峰值工作空间。

以上三项均**未证明为空白**。必须逐项对照 P13/P14/P15 的手工架构以及 P23/P24/P26/P27 的自动清理与 pebbling 模型。如果已有方法在相同接口下直接覆盖了问题，贡献就需要来自新的结构性质、求解算法、可证明界或显著而稳定的完整电路收益。

## 6. 首轮实验：先检验是否值得继续

遵循[项目研究计划](../../docs/research-plan.md)的 phase-oracle 接口：

```text
f(K) = AND_i [AES_K(P_i) = C_i]
O_f |K>|0_workspace> = (-1)^f(K) |K>|0_workspace>
```

### 第一步：建立可信基线与统一接口

- 复现 P03 corrected 的一个 AES-128 资源点；记录工具版本及任何解释后的偏差。
- 将 P06 窄结构与 P14 低深度架构置于相同门分解、明密文对数和调度语义下；P14 全文与实现是当前证据缺口。按具体选题加入 P05、P21、P22。
- 主实验用固定的两对数据 `r=2`；单对结果保留为口径核对。两对在理想密码近似下显著减少伪匹配，不代表对具体数据证明了唯一性。
- 独立验证小组件和缩小实例的相位与清理；完整 AES 使用参考加密与已验证组件组合，不依赖不可行的全态矢量模拟。

### 第二步：冻结组件，只变调度

| 轴 | 首轮对照 |
|---|---|
| 清理策略 | 尽早清理；合法的延后／全局清理；固定窗口清理；预算感知候选算法 |
| 密钥与数据 | 逐轮计算；保留部分轮密钥；必要时重计算；两对顺序／并行求值 |
| 计费模型 | 严格酉模型与测量辅助模型分别给结果；同模型内统一分解 |
| 宽度预算 | 从最窄可行完整实现到宽并行基线之间选择若干点；不可行点明确标出 |
| 反馈延迟 | 先用相对基本时间单位的参数扫描找转折；参数只用于敏感性分析，物理解释另需架构依据 |

先在小型轮依赖图上用穷举或精确求解确定最优调度，检查启发式是否真的发现了收益机制，再扩展到完整 AES。一般工具仅在输入接口和假设兼容时作为可运行基线；否则说明适配范围，不能把工具不支持直接记成资源劣势。

### 第三步：输出决定选题的数据

- 主图：`B–d_τ` 可行前沿与不同 τ 下的策略切换；表：完整 oracle／迭代的宽度、全深度、T-depth、各门族、测量及反馈依赖。
- 攻击层：固定成功率和期限后，计算所需处理器数及总成本，报告 DW 与 D²W 选优是否一致。
- 消融：只改跨轮清理、只改密钥调度、只改多对调度，以及联合变化；区分组件进步与调度进步。

### 继续／止步标准

| 观察结果 | 判断 |
|---|---|
| 同口径完整电路出现稳定的新 Pareto 点，且消融能说明方法机制 | 优先推进路线 A；约束评价用于解释收益适用区间 |
| 真实约束使旧指标选错方案，且新的优化策略在该区间有可靠收益 | 可加强路线 B，形成成本模型／决策方法与优化闭环 |
| 收益只来自遗漏比较、错误深度口径、旧版本基线或不同 `r` | 先修正比较，不能据此宣称优化 |
| 只组合已有组件，或仅在任意挑选的权重下获胜 | 证据不足以支持当前贡献定位；需重新识别独立的方法问题 |
| 基线无法复现 | 先形成精确的复现差距记录；暂不宣称超越现有最好结果 |

不预设“降低多少百分比必然可发表”。方法的新意、对照强度、可复现性与收益覆盖范围，比一个孤立降幅更重要。
